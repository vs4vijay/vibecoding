# Tasks

Execution model (per user direction): the main chat orchestrates only — implementation is done by a single subagent at a time, strictly sequentially (no parallel subagents). Each task below is one self-contained handoff: give the subagent the task text plus the paths to this change's artifacts (`openspec/changes/build-open-city-racing-game/` — proposal.md, design.md, `specs/*/spec.md`) and the repo (`/Volumes/Main/GitHub/projects/midtown-blitz`), since the subagent starts with no context. The subagent must end by demonstrating the task's verification (running dev server / scripts) and reporting results. The orchestrator reviews the diff and acceptance evidence before starting the next task.

- [x] 1.2 Fixed-timestep game loop (engine): 60 Hz accumulator loop with clamped catch-up (max 5 ticks/frame) and render-interpolation hook; frame-rate independence. Verify: with DevTools CPU 6x throttling the sim clock still matches wall clock within ~2% over a 30 s scripted test, and visual time never jumps more than one tick.
- [x] 1.3 Input abstraction (engine): keyboard mapping for WASD/arrows, Space, R, C, Esc with polled state and once-per-press edge events. Verify: debug overlay (behind a `?debug` flag) shows held keys live and edge events fire exactly once per press.
- [x] 1.4 Audio manager (engine): WebAudio graph with master gain, mute, lazy resume on first user gesture, and one synthesized test blip; volume applies live. Verify: after clicking the page a blip is audible; moving the volume value changes loudness immediately without reload.
- [x] 1.5 Renderer, camera rig, quality tiers (engine): WebGL renderer setup, smoothed chase-camera rig with follow target and at least two view modes, resize handling, and low/medium/high tiers (pixel ratio, shadows, fog/draw distance). ## 2. City world

- [x] 2.1 Deterministic city generation data (game): seeded PRNG (mulberry32-style) plus layout generator producing road grid (10×10 blocks, ~64 m blocks, ~14 m roads), block contents (building footprints/heights/colors), props, sidewalks, one park block and one tower landmark. Verify: generating twice from a fresh process yields byte-identical JSON dumps of the layout.
- [x] 2.2 City rendering (game): ground/roads with lane markings, raised sidewalks with curbs, instanced buildings/lamps/trees (per-instance color), park and tower meshes, daytime sky, directional sun with shadows at high tier, distance fog. Verify: dev server shows the recognizable city from an overhead debug camera; adjacent blocks vary in appearance; horizon fades into fog; renderer draw-call count stays under ~50 and a ~60 s overhead flight holds ~60 fps in the performance profiler.
- [x] 2.3 Collision world (game): spatial hash of static AABBs from buildings and blocking props, plus sidewalk elevation-step data; query API for circle/capsule bodies. Verify: scripted checks (node script against the generated layout) show building interiors and lamp posts as hits, road centers clear, and 10k queries complete in well under a frame budget.

## 3. Player vehicle

- [x] 3.1 Arcade car physics (game): kinematic bicycle-style model (speed-sensitive steering, lateral grip, handbrake slide), two-circle body vs collision world with substepped resolution, curb step crossing, impact response with camera-shake hook. Verify: scripted drive harness demonstrates top speed (~180–220 km/h scale) within ~8 s, head-on wall stop with no tunneling, glancing-wall deflection, and curb hop without sticking.
- [x] 3.2 Car visuals, camera, controls (game): low-poly stylized car (spinning wheels, steering fronts), chase camera wired to the rig, input mapping to throttle/brake-reverse/steer/handbrake/reset/camera. Verify: by hand in the dev build: hold-throttle run reaches top speed, handbrake slides through a 90° corner under control, camera stays behind through the turn, C cycles two views, reverse works from standstill.
- [x] 3.3 Reset and recovery (game): R resets the car upright on the nearest road with zero velocity within ~1 s; resting upside-down ~2 s shows a reset prompt (placeholder UI ok). Verify: flip the car (debug flip helper or curb hit), recover with R, then let it rest flipped to see the prompt fire. (By-hand dev-server check delegated to the orchestrator; scripted coverage in scripts/recovery-test.mjs.)

## 4. Traffic

- [x] 4.2 AI traffic and pooling (game): ~24 pooled cars doing lane-keeping, intersection turns with slowdown, ahead-probe braking for cars and the player, and seamless recycling beyond a player radius. Verify: overhead observation shows lane discipline and a car stopping behind a stopped player then resuming; driving edge-to-edge across the city keeps traffic nearby throughout with no visible teleports. (By-hand overhead observation delegated to the orchestrator; scripted coverage in scripts/traffic-test.mjs.)
- [x] 4.3 Parked cars and car-car collisions (game): parked rows along curbs registered as static colliders plus instanced meshes; player-vs-traffic and traffic-vs-traffic separation with momentum exchange. Verify: T-boning a moving traffic car deflects/spins both without interpenetration; a parked car is solid; a stopped lane blockage makes queueing traffic pile up rather than overlap.

## 5. Game flow, races, UI

- [x] 5.1 Save and settings module (game): namespaced localStorage blob (`midtown-blitz.save.v1`) holding settings + records, defaults on missing/corrupt data, and a settings screen (volume, mute, quality) applying changes live. Verify: change settings, reload, they persist; manually corrupt the key, reload, game boots with defaults and later re-saves cleanly.
- [x] 5.2 Mode state machine and menus (ui/game): menu (title, event list with records, cruise, settings), pause (resume/restart/quit), results screens; transitions tear down timers, audio, and mode UI completely. Verify: click through every path including mid-race restart and quit-to-menu; after quit, no race timers, race audio, or HUD elements remain and the menu renders normally.
- [x] 5.3 HUD (ui): speedometer, race timer, countdown display, reset prompt, and checkpoint guidance (world marker: light beam + ring; screen-edge directional arrow for off-screen checkpoints; pass chime). Verify: while driving a test route the edge arrow tracks an off-screen checkpoint, passing it chimes and advances the target, checkpoints cannot be taken out of order, and the countdown blocks throttle.
- [x] 5.4 Blitz races and Cruise (game): three Blitz route definitions (start, ordered checkpoints, time limit, gold/silver/bronze thresholds) and one race state machine (countdown → running → win/fail) shared with a no-objective Cruise mode. Verify: win a route under its gold time → results; let a timer expire → immediate failure screen with retry/menu; Cruise runs indefinitely with no fail state and exits only via pause.
- [x] 5.5 Records and medals end-to-end (game/ui): finish times map to medals, best time and highest medal persist per race, event list shows them. Verify: finish a race → reload → menu shows the saved best and medal; a faster run updates the best and the results screen calls out the new record.
