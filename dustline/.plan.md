# Dustline — design spec & implementation history

A Counter-Strike-inspired multiplayer FPS in the browser: 5v5 team deathmatch
on a dust-style map, server-authoritative netcode, zero assets.

Full v1 plan and acceptance gates: [`../docs/plans/dustline-v1-plan.md`](../docs/plans/dustline-v1-plan.md)

## Design pillars

- **Server-authoritative everything** — the client predicts and renders, the
  server decides. 60 Hz fixed tick, 30 Hz snapshots, per-input acks.
- **Fair hit registration at real latencies** — the server keeps a 60-tick
  position history and rewinds targets to what the shooter actually saw
  (RTT/2 + snapshot age, measured server-side via app-level ping/pong).
- **Instant local feel** — inputs are applied and rendered immediately
  (fixed 60 Hz regardless of display refresh rate); server corrections are
  eased over 100 ms so reconciliation never snaps the camera.
- **Zero assets** — procedural map geometry, WebAudio-synthesized sound;
  PWA precache stays tiny and license-clean.
- **Best-effort persistence** — PGLite with SQL-atomic stat accumulation and
  idempotent match writes; DB failure degrades to logs, never crashes the loop.

## Implementation history (summary)

| Milestone | What landed |
|---|---|
| Rename | cs-clone → dustline; shared-first build order fixed; harness hardened |
| Prediction | seq-tagged inputs, ack reconciliation, eased corrections; bit-exact client/server movement parity |
| Lag comp | PositionHistory ring buffer + RTT-aware rewind depth |
| Collision fix | standing-contact exclusion (floor no longer acts as a wall), mirrored byte-exactly client-side |
| Audio | procedural WebAudio engine, M-key mute, persisted settings |
| Persistence | match/player/match-player rows, kd_ratio accumulation, GET /leaderboard, L-key panel |
| Netcode completion | server-emitted hit/kill/death/matchStart/matchEnd messages (kill feed, death screen, match sounds) |
| Security/polish | scoreboard XSS fix, RTT sample cap, fixed-timestep input accumulator |
