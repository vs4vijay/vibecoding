<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parser output to storage writer | Parsed strings treated as untrusted for index-size purposes (giant lines could bloat the terms index) |
| test shim to production IDB | fake-indexeddb semantics assumed to match browser IndexedDB for compound and multiEntry behavior |
| npm registry to local install | New third-party code enters the supply chain via bun add |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | dexie / fake-indexeddb tarballs | high | mitigate | Blocking human checkpoint verifies both packages on npmjs.com before install; versions pinned to 4.4.5 / 6.2.5 |
| T-02-02 | Denial of service | tokenize() on pathological message text | medium | mitigate | Truncate tokenization input to first 2000 chars and cap terms at 200 per message in this plan |
| T-02-03 | Tampering | version(1) schema block | low | mitigate | Never edit the released version block; future changes add new versions only |
| T-02-04 | Information disclosure | IndexedDB cross-origin access | low | accept | Browser same-origin policy isolates per-origin data; no action, do not weaken with cross-origin workers |
| T-02-SC | Tampering | npm installs (dexie, fake-indexeddb) | high | mitigate | Slopcheck-equivalent human checkpoint gates the install; checkpoint is never auto-approved |
</threat_model>
