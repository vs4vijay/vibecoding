  async searchMessages(query: string, opts?: { chatId?: number; limit?: number; candidateCap?: number }): Promise<{ total: number; results: MessageRecord[] }>
    - tokens = tokenize(query); tokenize('') and tokenize('!!!') yield [] — return { total: 0, results: [] } (guard contract preserved from the migrated tests).
    - Build the collection in Dexie's documented order for multiEntry anyOf: let col = this.db.messages.where('terms').anyOf(tokens); when opts.chatId is a finite number, col = col.filter((m) => m.chatId === chatId) BEFORE distinct (filter-then-distinct is the documented safe order — the existing searchTermsInChat already follows it); then col = col.distinct() for id-dedup.
    - total = (await col.primaryKeys()).length — primary-key ids only, no record materialization; this is the exact SC-5 count.
    - candidates = primary keys sorted descending (newest first) then sliced to candidateCap (default 200); total = ids.length (exact). Sorting is required because anyOf+distinct primaryKeys are grouped per-term ascending-within-term, not globally by import order.
    - records = await this.db.messages.bulkGet(candidate ids); sort by timestamp desc, id desc tiebreak; slice to limit (default 50); return { total, results }.
    - Never call toArray on the terms collection without a prior bound; the only unbounded op is primaryKeys() (ids only).

  ADD window-seek primitive on MessageRepository:

  async getWindowAt(chatId: number, msgId: number, limit: number): Promise<{ messages: MessageRecord[]; targetId: number } | null>
    - target = await this.db.messages.get(msgId); return null when missing or target.chatId !== chatId (05-02 falls back to a normal newest-open; never throw).
    - half = Math.floor((limit - 1) / 2). Older block: same-timestamp siblings with id < target.id (equals + filter + sort id desc, limit half, take all) then rows strictly below [chatId, target.timestamp] via the getOlderPage bound shape, reversed, limit remainder; reverse the combined block to chronological. Newer block: same-timestamp siblings with id > target.id ascending, limit half, take all; then rows strictly above [chatId, target.timestamp] ascending, limit remainder. Every read has an explicit .limit() — satisfies the repo-layer guardrail "every read path is limit-bounded".
    - Return chronological messages = [...olderChronological, target, ...newerChronological], plus targetId. Whole read is bounded by limit via keyset bounds — no unbounded collection scans.
