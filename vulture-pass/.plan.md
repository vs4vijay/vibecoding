# Design

## Context

Greenfield repo; the entire game is new code. House stack from sibling projects (midtown-blitz, late-again): **Vite + three + vanilla ESM JavaScript**, layered `src/engine` / `src/game` / `src/ui` / `src/main.js`. No existing code or specs to integrate with. Content targets: 1 region, 2 towns, 3+ cars, 4+ weapons, 1 boss, all original IP (see proposal). Reference screenshots of the 2005 game live in `.zcode/research/shots/` for mood only.

## Goals / Non-Goals

**Goals:**
- A complete, shippable vertical slice loop: title → overworld → towns → ambush combat → progression → boss → sandbox, with save/resume.
- Combat and driving *feel* that is tunable without engine changes (data-driven).
- Clean seams so later changes (more regions, multiplayer, full roster) extend without rewrites.

**Non-Goals:**
- Multiplayer of any kind (design only keeps a seam for it).
- Mobile/touch, gamepad support beyond what the browser gives free.
- Full campaign arc, all 16 car / 18 weapon equivalents, R/C car bombs and JATO rockets (later changes).
- Pixel-perfect recreation of the 2005 game's look.

## Decisions

### D1 — Stack: Vite + three, vanilla ESM JS, no game framework
Matches house style exactly. Alternatives: TypeScript (better safety; rejected — neither sibling uses it on the client, consistency wins for a solo-maintained game), Phaser/PixiJS (native 2D fit for top-down; rejected — user explicitly wants Three.js, and 3D lighting elevates the desert mood cheaply), react-three-fiber (rejected — framework churn, no UI complexity that needs it).

### D2 — One Three renderer, many scenes; UI is DOM
A single `WebGLRenderer`/`canvas` hosts three scene types — **town**, **combat arena**, **(map is not 3D, see D4)**. All menus, HUD, shop interfaces, and comic cutscenes are DOM/SVG overlays above the canvas. DOM UI is cheaper to build, style, and make readable than in-canvas UI, and matches the pulp/sepia art direction (paper textures, halftone, captions). State machine (`TITLE → OVERWORLD ⇄ TOWN → COMBAT → CUTSCENE …`) governs which scene renders and which overlays show; each state owns enter/exit.

### D3 — Camera: high-angle perspective follow-cam
Perspective camera locked ~75° above and behind the player car, tight follow, slight look-ahead in velocity direction. Gives the top-down tactical readability the combat needs (aim side always unambiguous) while keeping 3D depth for lighting/explosions. Alternative: true orthographic top-down (more faithful to 2005, flatter mood; can be a settings toggle later — camera is one module).

### D4 — Overworld map is a styled DOM/SVG screen, not a Three scene
The original's sepia hand-drawn map is UI art, not a world. An SVG map with paper/halftone CSS treatment, clickable towns, road paths, day counter, and boss-gate locks delivers the aesthetic for a fraction of the effort. Travel is an authored interaction: pick destination → consume days → roll ambush → spawn combat arena (or arrive).

### D5 — Custom arcade physics; no physics engine
Car model: heading + velocity + grip/drift factor + off-road drag multiplier (road surface tagged on ground data); collisions circle-vs-circle and circle-vs-AABB with positional push-out only — **no collision damage** (spec). Projectiles are raycast-instant (bullets) or swept bodies (rockets); explosions apply radial damage. cannon-es/Rapier rejected: the game needs ten cars and dumb bullets, and hand-tuned arcade feel beats engine realism here; also keeps the fixed-timestep sim deterministic — which is exactly the seam a future multiplayer change needs (combat steps take *intents* in, produce state out; remote players later = more intent sources).

### D6 — Data-driven content, code-free balancing
`src/game/data/*.js` ESM modules export plain objects: `cars`, `weapons`, `goods` (base prices), `towns` (price modifiers, inventories), `jobs` (templates), `boss`, `cutscenes` (panel scripts). Same philosophy as the original's Lua data layer. Prices per town = base × town modifier × daily seeded drift, so trading patterns stay stable enough to learn but not static.

### D7 — Fixed-timestep simulation, decoupled render
`engine/loop.js`: sim at 60 Hz fixed (accumulator), render at rAF with interpolation of transforms. Prevents feel changes on 120 Hz displays and keeps combat replayable/deterministic. Entities are plain objects; systems (input, driving, weapons, projectiles, damage, AI) mutate them in sim steps. No ECS framework — a `CombatScene.entities` array + system functions is enough at this scale.

### D8 — Enemy AI: three archetypes
`scout` (orbits at mid-range, pistol), `bruiser` (rams-lane pressure, shotgun), `gunner` (keeps distance, MG burst). Wave composition scales with cargo value (spec) via a points budget. Boss = scripted wave ladder: N minion waves → boss car with phase change at 50% health.

### D9 — Dual-mount firing resolution
Aim direction (mouse world point) vs. car heading: sign of the 2D cross product picks the mount. One aim point, both mounts always visible in HUD. This is the signature mechanic — it gets its own tiny module (`game/weapons/mounts.js`) and its own tuning constants, so feel iteration is isolated.

### D10 — Save: versioned localStorage snapshot of game state only
`engine/save.js` serializes the `GameState` object (money, day, car id + health, mounts, cargo, upgrades, insurance, job states, boss flag, location) with a `version` field. Scenes/entities are rebuilt from state on load. Defensive load: unknown version or parse error → ignore save, offer new game (never crash).

### D11 — Art & audio: programmatic/CC0, palette-locked
Cars/buildings/props from three primitives + vertex colors at build time (no modelling pipeline needed for the slice); desert palette defined once in `data/palette.js` so every scene shares hue discipline. Comic panels are SVG frames with placeholder illustration shapes + caption typography — structure now, real drawings swapped in later without code change. Audio: WebAudio, small set of CC0 SFX (engine, gun classes, explosion) + one original/CC0 guitar sting for cutscenes; `engine/audio.js` gated behind first user gesture (autoplay policy).

## Risks / Trade-offs

- [Combat/driving feel arrives late and wrong] → earliest tasks deliver a drivable car + one enemy + one weapon in a bare arena ("feel slice") before any economy/UI; all feel constants live in data modules.
- [Scope creep toward the full game] → the spec delta is the fence: one region, subset rosters; anything beyond is a future change. Tasks sized accordingly.
- [Top-down 3D readability (visual noise at shallow angles)] → high camera angle, palette lock, strong silhouettes, minimal ground clutter; camera module is isolated for quick FOV/angle tuning.
- [Deterministic sim discipline erodes under UI pressure] → UI never touches entities; it reads state and dispatches intents. Enforced by module boundaries (`game/` never imports DOM, `ui/` never mutates sim state directly).
- [localStorage save loss/corruption] → versioned, defensive load; save on every battle outcome + town entry + explicit save, not just exit.
- [Original-IP drift (someone pastes 2005 names/assets in)] → content audit task before completion; research screenshots stay under `.zcode/` and are never imported.

## Migration Plan

Greenfield — no migration. Rollback is `git revert`; the game is static assets after `vite build` with no backend.

## Open Questions

- Final names for protagonist, gang, towns, region (creative, deferrable to apply; placeholder names in data modules now).
- Exact tuning numbers (prices, damage, XP curve) — data-driven, tuned during apply's playtest task.
- Whether the boss-gated locked routes in the slice visibly hint at the future region-2 content or just say "locked" — cosmetic, decided during apply.

# Proposal

## Why

*Mexican Motor Mafia* (2005) is a beloved but stranded Windows-only indie game — a top-down car-combat/trading hybrid that modern audiences can't play. We want an original web-based homage: same genre DNA (revenge road-story, bandit bosses, buy-low/sell-high trading, drive-by combat), our own characters and art, running in the browser via Three.js. This change delivers the first playable milestone: a one-region vertical slice that proves the core loop is fun before we invest in the full campaign.

## What Changes

- **Greenfield web game** in this repo: Vite + Three.js + vanilla ESM JavaScript (matches the stack of our sibling projects midtown-blitz and late-again).
- **Original homage IP** — no names, story text, art, or audio from the commercial game. Our own drifter protagonist, bandit gang, towns, and region set on a fictional desert borderland; pulp-comic/sepia aesthetic inspired by, not copied from, the original.
- **Vertical slice on one region** (~2 towns + surrounding highways), single-player only:
  - Top-down (chase-cam feel) 3D driving with car handling, health, and explosions.
  - Combat with the signature **dual-side weapons**: fire the left-mounted weapon when aiming left of the car, the right one when aiming right; unlimited ammo, car damage is the cost.
  - **Overworld map travel** between towns with a day counter and road ambushes whose strength scales with cargo value.
  - **Towns with hotspots**: trade goods (per-town prices, cargo capacity), job board (delivery runs and bounty hunts), gun shop (weapons), garage (cars + repairs).
  - **Progression**: combat XP feeds three tracks (reload speed, field repair, map sight); money buys cars, weapons, repairs, and insurance.
  - **First boss**: intro screen, multi-wave fight, comic-panel victory cutscene; beating him leaves the region playable as an endless trader/bandit sandbox.
  - **Save/load** (suspend-style) in localStorage.
- **Out of scope for v1** (deliberately): multiplayer (design will note WebSocket seams), remaining regions/bosses of the full arc, the 16-car/18-weapon full roster (slice ships a representative subset), mobile touch controls.

## Capabilities

### New Capabilities
- `core-game`: the complete playable vertical slice — driving & combat model, overworld travel, town economy (trade/jobs/gun shop/garage), progression, first boss encounter with cutscenes, death/insurance rules, save/load, and the pulp art direction that ties it together.

### Modified Capabilities

(none — greenfield project, no existing specs)

## Impact

- **New code**: entire repo becomes a Vite package (`package.json`, `index.html`, `src/engine`, `src/game`, `src/ui` layered like midtown-blitz). No existing code is touched.
- **New dependency**: `three` (runtime), `vite` (dev). Nothing else planned — physics via own arcade model, no physics engine.
- **Assets**: original placeholders/programmatic art for the slice (low-poly cars, desert palette, comic-panel frames); CC0 or generated audio stings. Reference screenshots from the 2005 game live in `.zcode/research/` for style guidance only — never shipped.
- **Future changes build on this**: more regions/bosses (delta on `core-game`), multiplayer (new capability), full car/weapon roster.
