## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Denial of Service | parseFile.ts preamble handling | low | mitigate | Lines before first timestamp header are accumulated but capped at 50 lines of preamble. Beyond that, discard with a counted warning. Prevents preamble (e.g. pasted novel) from being treated as a single message body. |
| T-01-06 | Denial of Service | patterns.ts 14+ regex iteration | low | mitigate | Each line is matched against up to 14 patterns in worst case. This is O(patterns) per line — acceptable at < 100K lines. Monitor performance in test suite. If parsing approaches 1 second per 10K lines, consider pattern caching per detected format (skip already-matched family). |
| T-01-07 | Tampering | fixtures/chattopdf fixture JSON | low | accept | The fixture JSON is committed to the repo and reviewed during PR. An attacker with write access to the repo could modify the fixture to produce false-negative results. Acceptance rationale: single-user project, no supply chain risk from test fixtures. |
| T-01-08 | Tampering | normalize.ts fullwidth/full CJK normalization | low | mitigate | Normalization only replaces specific well-known Unicode ranges (fullwidth digits U+FF10-U+FF19, fullwidth colon U+FF1A, CJK AM/PM). It does not use any broad Unicode property classes that could be exploited for normalization bypass. |
| T-01-SC | Tampering | Benchmark data download vulnerability | low | accept | The benchmark JSON is fetched from a published URL. Downloaded content is parsed via JSON.parse only. No code execution risk from JSON data. If the URL is unreachable, the synthetic fallback fixture is used instead. |
</threat_model>
